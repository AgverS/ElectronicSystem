# Electronic Journal — demonstration build

An interactive demonstration of a role-based electronic journal for a college:
attendance, grades, timetables, laboratory work and academic reporting, seen
through three roles — administrator, teacher and student.

This is a **demo**, built to be sent to universities and colleges as an example
of work. There is no registration and no sign-in: visitors pick a role and start
exploring.

## How the demo works

**No server, no database.** The whole application is a static export. It runs
entirely in the visitor's browser.

**Every visitor gets their own data.** The dataset is seeded from
`lib/demo-db/seed.ts` and stored in the visitor's own `localStorage`. Anyone can
add lessons, change grades, edit the timetable — and nobody else sees it.
"Reset demo data" restores the original state.

**Nothing to configure.** No environment variables, no connection strings, no
secrets. Build it and drop the output on any static host.

**Isolated from anything else on the same domain.** Browser storage is shared
across a whole origin rather than per directory, so two demos published under
one account — `example.github.io/one/` and `example.github.io/two/` — would
otherwise overwrite each other. Every key this demo owns is namespaced by the
base path it is served from (see `lib/demo-db/storage.ts`). If two builds ever
share a base path, set `NEXT_PUBLIC_DEMO_ID` to tell them apart.

### Where the data layer came from

The original application ran on PostgreSQL through Prisma. Rather than rewrite
every query, `lib/demo-db/` implements a small query engine that speaks the same
dialect — `findMany`, `include`, `where`, `orderBy`, `groupBy`, cascade deletes
and so on — over an in-memory dataset. `lib/prisma.ts` points at it, so the
data-access code reads the way it always did.

`pnpm check:demo-db` runs 45 assertions covering every query shape the
application relies on.

## Languages

English is the default. French, Spanish, German and Russian are selectable from
the switcher in the sidebar.

Adding a language is one file:

1. Copy `lib/i18n/locales/en.ts` to `lib/i18n/locales/<code>.json`, translating
   the values.
2. Add the language to `LOCALES` in `lib/i18n/config.ts`.

Any key a translation has not covered falls back to English, so a partial
catalog still renders a complete interface.

## Running it locally

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

Other commands:

```bash
pnpm build          # static export into out/
pnpm start          # serve the built output
pnpm typecheck
pnpm lint
pnpm check:demo-db  # verify the demo database engine
```

## Branches and deployment

- **`dev`** — where work happens. Every push runs type checking, linting, the
  demo-database checks and a build (`.github/workflows/ci.yml`).
- **`main`** — production. Merging `dev` into `main` builds the static export and
  publishes it automatically (`.github/workflows/deploy.yml`).

To release:

```bash
git checkout main
git merge dev
git push origin main     # deployment starts on its own
```

### One-time setup

In the repository on GitHub, open **Settings → Pages** and set **Source** to
**GitHub Actions**. The first push to `main` then publishes the site.

The workflow builds with the repository's base path, so a project site served
from `/ElectronicSystem/` works without further configuration. For a custom
domain served at the root, set `NEXT_PUBLIC_BASE_PATH` to an empty string in
`.github/workflows/deploy.yml`.

Any other static host works too — build with `pnpm build` and upload `out/`.

## A note on the content

The institution, its staff and its students are invented. Names, grades,
timetables and disciplinary records are all generated by `lib/demo-db/seed.ts`.
No real person's data appears anywhere in this repository.
